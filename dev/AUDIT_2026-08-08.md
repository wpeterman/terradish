**Date:** 2026-08-08. **Version audited:** 0.0.44, delivered as 0.0.45.
**Scope:** mathematical correctness, documentation completeness, unit-test
depth, vignette accuracy and consistency, CRAN compliance.

This is a fresh audit, not a re-read of `dev/CRAN_READINESS_REVIEW.md`. Where
that document's items were re-checked, the outcome is noted.

## 2. Mathematical verification

The package's analytic derivatives had never been checked against numerical
differentiation anywhere in the test suite. `terradish_algorithm()` has a
`validate = TRUE` path that computes `numDeriv` comparisons, but nothing
exercised it. Four peripheral paths had finite-difference tests (the directed
gradient, the Gaussian-scale conductance derivatives, the hierarchical
penalized gradient, `wishart_drift_covariates`); the central estimator did not.

Every derivative path was checked against Richardson-extrapolated finite
differences on the bundled `melip` data (8 focal sites, 22,443-vertex graph).

| Conductance model | Measurement model | grad rel. err | Hessian rel. err |
|---|---|---|---|
| loglinear | `leastsquares` | 9.7e-09 | 5.7e-10 |
| loglinear | `generalized_wishart` | 2.3e-08 | 3.9e-10 |
| loglinear | `wishart_covariance` | 2.0e-08 | 3.9e-09 |
| loglinear | `mlpe` | 1.3e-08 | 6.5e-10 |
| loglinear | `mlpe_covariates` | 1.3e-08 | 7.3e-10 |
| loglinear | `wishart_drift_covariates` | 2.0e-08 | 3.0e-09 |
| loglinear | `pair_subset_measurement_model` | 1.1e-08 | 9.8e-10 |
| linear | `leastsquares` | 2.7e-09 | 2.4e-09 |
| smooth (natural spline) | `leastsquares` | 3.3e-08 | 4.1e-08 |
| loglinear | `wishart_covariates` | 4.3e-08 | **1.6e-02** |

The last row is a real defect, described in section 3.

Also verified by hand and numerically:

* **Sign conventions are consistent.** `terradish_algorithm()$objective` is the
  negative log-likelihood (documented as such in `\value`) and is minimized;
  the Hessian at the optimum is positive definite; `fit$loglik` carries the
  opposite sign; `AIC(fit)` equals `-2 * logLik + 2 * df` exactly; the
  likelihood-ratio statistic in `anova()` equals `2 * diff(loglik)` on the
  right degrees of freedom.
* **The Wishart `nu` scaling is exactly as documented.** Across `nu` of 100,
  1000, and 10000 on the same response, point estimates were identical to
  seven significant figures, standard errors scaled by exactly `sqrt(10)`
  (ratio 3.162278), and the log-likelihood scaled linearly. This confirms the
  vignette's quantitative claims.
* **`wishart_covariates` covariance-branch algebra** was verified symbolically:
  the objective `nu/2 (log|Sigma| + tr(Sigma^-1 S))`, the gradient
  `nu/2 (A - A S A)`, and the second-derivative operator all match the Wishart
  log-density derivatives term for term.
* **C++ side** registers native routines with `R_registerRoutines` and
  `R_useDynamicSymbols(dll, FALSE)`, writes nothing to stdout/stderr, and
  contains no `exit`/`abort`/`assert`. `LinkingTo` on both RcppArmadillo and
  RcppEigen is genuinely used.

## 3. Defects found and fixed

### 3.1 Profile Hessian is wrong when a nuisance parameter sits on a bound (HIGH)

`radish_subproblem()` forms the profile-likelihood curvature by adding the
implicit-function correction

```
dphi/dE = -[d2l/dphi2]^-1 d2l/dphi dE
```

using the **full** nuisance Hessian. That stationarity argument only holds for
nuisance parameters free to move. A parameter pinned at an active box
constraint has `dphi/dE = 0` and must be excluded.

`wishart_covariates()` constrains every kernel coefficient to be non-negative.
Whenever one is estimated at exactly 0, which is the common outcome when the
environmental kernel has no support in the data, the correction was applied
along a direction the optimizer cannot move. In the bundled example this
inflated the Hessian by 1.6%, biasing every standard error, confidence
interval, and Wald p-value derived from it. Estimates, log-likelihoods, and
gradients were unaffected (the gradient is exact by the envelope theorem).

The source carried two unanswered developer comments at exactly these two
lines: `#why is this nonzero when on boundary?`.

**Fix.** `.free_parameter_index()` identifies the inactive set from the box
constraints the measurement model declares, and
`.constrained_inverse_hessian()` inverts only that block, zero-padding the
pinned rows and columns. Verified: relative error against numerical
differentiation drops from 1.6e-02 to 4.1e-08, while `wishart_covariance` and
`wishart_drift_covariates` are bit-for-bit unchanged. At `lambda = 0` the
corrected Hessian now equals the plain `wishart_covariance` Hessian, which is
the model the fit collapses to.

Note this is distinct from the existing `boundary` flag, which only tracks the
IBR slope (`tau` or `beta`) hitting zero and zeroes all derivatives. The case
fixed here is a *partially* active constraint set: `tau` interior, a kernel
coefficient pinned.

### 3.2 `cores > 1` was a silent no-op in the core algorithm (MEDIUM)

`R/radish_algorithm.R` gated its parallel Hessian branch on

```r
identical(environmentName(environment(terradish_algorithm)), "namespace:terradish")
```

`environmentName()` on a namespace returns the bare package name
(`"terradish"`), never `"namespace:terradish"`, so the condition was always
false. The `cores` argument of `terradish_algorithm()` and `terradish()` did
nothing, and the whole PSOCK derivative-parallelization path was dead code.

**Fix.** The guard now calls the shared `.use_namespace_workers()` helper, plus
an explicit requirement that the solver state contains no external pointer:
the `cholmod_cpp_cached` backend and the AMG backend both hold `externalptr`
handles that cannot survive serialization to a PSOCK worker.

### 3.3 Worker mode was chosen from the working directory (MEDIUM)

`.use_namespace_workers()` returned FALSE, meaning "have the workers `source()`
the R files", whenever `file.path(getwd(), "R", "radish_grid.R")` existed. A
maintainer sitting in the package source tree while using the *installed*
package would silently get workers running a different copy of the code.

**Fix.** The decision is now made from the namespace itself: the function tests
that it is running inside a real installed namespace, and distinguishes an
installed layout (which has the `R/<pkg>` lazy-load stub) from a
`devtools::load_all` source tree (which has `R/*.R` files instead). Verified
against both layouts.

### 3.4 Dead benchmark code in `R/` (MEDIUM)

`wishart_simulate_distance()`, `wishart_simulate_experiment()`, and
`run_benchmarks()` formed a closed cluster in `R/genetic_distance.R` called by
nothing else. They called `set.seed()` three times without saving or restoring
the RNG, which is the CRAN policy violation the previous review recorded as
fixed (it was fixed in the three exported paths, not here); they depended on
`RandomFields`, archived on CRAN; and they called `terradish_algorithm()` and
`terradish_distance()` with argument orders that no longer exist, so they could
not run.

**Fix.** Moved to `inst/benchmarks/generalized-wishart-timing.R` with a header
recording why. The orphaned `.randomfields_*` and `.nloptr_bobyqa` accessors
were removed from `R/package_access.R`, and `nloptr` dropped from `Suggests`.

### 3.6 The hierarchical vignette contained code that is not valid R (MEDIUM)

`vignettes/hierarchical-conductance.Rmd` showed

```r

```

as the step that produces the response, and computed a `blob` object that the
shown code never used. A reader could not reproduce the worked example. Only 1
of the vignette's 11 chunks executes at build time, so nothing caught it.

**Fix.** The simulation chunk now carries the complete, runnable code from

### 3.7 README claimed a dependency that is neither required nor off-CRAN (MEDIUM)

`README.md` said "corMLPE is also required (not on CRAN)" and pointed at
`devtools::install_github("nspope/corMLPE")`. `corMLPE` is on CRAN, and
`terradish` never calls it: the package implements MLPE itself. It was an
unused `Suggests`. Corrected in the README, the getting-started vignette, and
DESCRIPTION. Both install sections now lead with `install.packages("terradish")`
rather than a source install.

### 3.8 Seventeen exported S3 methods had no documentation at all (MEDIUM)

Every method for `terradish_directed` and `terradish_hierarchical` objects
carried a bare `#' @export` with no title, so roxygen generated no help page.
A user fitting either of the two most complex models in the package and calling
`summary()`, `confint()`, `vcov()`, or `plot()` had nothing to read.

**Fix.** Two new topics, `?terradish_directed_methods` and
`?terradish_hierarchical_methods`, documenting every method: what each returns
element by element, the scale each quantity is on, how to back-transform, how
to read the coefficient table, and how to interpret the field `sd`/`edf` and
the two log-likelihoods the hierarchical print shows. Both carry runnable
`\donttest` examples and cross-link to the relevant vignette.

### 3.9 Two vignettes could not be re-built from the tarball (BLOCKER)

`R CMD check --as-cran` with vignettes enabled returned **1 ERROR**:

* **`simulation-design.Rmd`** called `readRDS("vignette-nu-power.rds")` and

  the check's environment, and knitting: previously an error, now succeeds in

* **`spline-conductance.Rmd`** failed with
  `Error in library(): there is no package called 'patchwork'`, described next.

### 3.10 `patchwork` used in a vignette but never declared (BLOCKER)

`vignettes/spline-conductance.Rmd` calls `library(patchwork)` in two chunks
that execute at build time, but `patchwork` was in neither `Imports` nor
`Suggests`. The previous review never saw this because it checked with
`--no-vignettes`; with vignettes enabled it is a NOTE
(`'library' or 'require' call not declared from: 'patchwork'`), and on any
machine without `patchwork` installed the vignette build would fail outright.

`patchwork` is installed on the audit machine, so `R CMD build` knitted the
vignette without complaint; the check's vignette re-build runs against a
restricted library that only carries declared dependencies, which is where it
broke. Any user or CRAN machine without `patchwork` would have hit the same
failure.

**Fix.** `patchwork` added to `Suggests`, and both live chunks now guard on
`requireNamespace("patchwork", quietly = TRUE)` with a one-panel-per-page
fallback, so the vignette builds either way. Verified by re-knitting from a
clean directory.

## 5. Vignettes

Ten vignettes. All ten already shared the same YAML, engine declaration,
`\Vignette*` metadata, and setup-chunk conventions. 139 of 200 chunks (70%)
execute at build time, so most shown code is validated by the build itself.

**Consistency of format was the main gap.** The house convention closes a
vignette with a quick-reference block, a summary-of-key-functions table, and a
see-also list, in that order. Before this audit only `large-landscapes` had all
three; two vignettes had a summary table, three had a see-also, and the
core `getting-started` vignette ended abruptly on its code block with no
forward links at all. `large-landscapes` also used H1 headings where every
other vignette uses H2, which changes the numbering depth in the rendered TOC.

All ten now carry the full three-part closing in house order, with a
quick-reference block added to `model-comparison` and
`gaussian-scale-optimization`, and heading levels normalized.
`gaussian-scale-optimization`'s "Companion vignettes" heading was renamed
"See also". `getting-started` now links to all nine companions rather than five.

**Code validation.** A parser was run over every chunk in every vignette and
every `\examples` block in every Rd file, checking each call against the actual
formals of the function it names. After correcting two calls introduced during
this audit, there are no argument-name mismatches anywhere. (The check catches
wrong or invented argument names; it cannot catch a wrong positional order.)

**Caching.** The precompute design is sound and works. `vignettes/precompute.R`
and two scripts in `dev/` generate four `.rds` artifacts that are committed to
git; `R CMD build` knits the vignettes with them present and then excludes them
from the tarball via `.Rbuildignore`, so the shipped HTML carries real results
while the tarball stays small. Two caveats worth knowing:

1. If an `.rds` goes missing the vignettes degrade silently: every result chunk
   is `eval = have_res`, so the document knits without error and simply omits
   its results. A build-time warning when `have_res` is FALSE would make that
   visible.
2. `vignettes/precompute.R`'s header lists three output files and omits
   `vignette-hierarchical.rds`, which is produced by
   `dev/make_vignette_hier.R`.

## 6. Follow-up round: the three items that needed a decision

Three items from the first pass changed user-visible behavior, so they were
left for the maintainer. All three were subsequently resolved.

### 6.1 A verbose switch, and quiet by default (RESOLVED)

`terradish()` had `control = NewtonRaphsonControl(verbose = TRUE, ...)` as its
default, so every fit printed a Newton-Raphson iteration trace, and it printed
with `cat()`, which `suppressMessages()` cannot silence. Under `R CMD check`
the test log was mostly optimizer dumps.

**Done.** `terradish()` gains a `verbose` argument defaulting to `FALSE`, and
all 27 `cat()` traces across `newton_raphson.R`, `bfgs.R`, `hager_zhang.R`,
`armijo.R`, and `terradish_scale_optim.R` now use `message()`.
`terradish_hierarchical()`, `terradish_assess_settings()`, and
`terradish_scale_optim()` also default to `verbose = FALSE`.

The precedence rule is that an explicitly supplied `verbose` overrides
`control$verbose`, while an untouched `verbose` leaves a hand-built `control`
alone, so existing `control = NewtonRaphsonControl(verbose = TRUE)` code keeps
working. `verbose` deliberately does not reach `ls.control`: the line-search
trace is an order of magnitude noisier and stays a separate opt-in through
`NewtonRaphsonControl(ls.control = HagerZhangControl(verbose = TRUE))`.

Verified in `tests/testthat/test-verbose-and-tau2.R`: the default fit is
`expect_silent`, `verbose = TRUE` is `expect_message`, `suppressMessages()`
silences it, an explicit `verbose` beats a loud `control`, a loud `control`
alone still works, a non-logical `verbose` errors, and the switch does not
change the coefficients or the log-likelihood.

### 6.2 The tau2_grid singularity (RESOLVED)

When the selected `tau2` sat at a grid edge the fit warned "Consider widening
`tau2_grid`". Following that advice provoked
`system is computationally singular: reciprocal condition number = 2e-16` from
`BoxConstrainedNewton()` and lost the entire fit. The failure comes from the
warm start carried in from the previous grid point, not from the tau2 value in
isolation, which is why a cold-start fit at the same tau2 succeeds.

**Done.** Each grid point is wrapped in `tryCatch()`. A failure records `NA`
in the `tau2_selection` table, keeps the last good warm start, and names the
skipped values in a warning. `tau2` is selected from the points that worked,
and the grid-edge warning now describes the edge of the *usable* range rather
than the requested grid, since a maximum sitting next to a skipped point is
just as uninformative. A fixed `tau2` that fails now reports what happened and
what to try instead rather than surfacing a raw LAPACK error.

Verified: the `c(0.1, 1, 10)` grid that previously aborted now completes,
selects `tau2 = 1`, records `NA` at 10, warns about both the skip and the edge,
and still recovers the generating coefficients (0.4995 and -0.4005 against a
truth of 0.5 and -0.4).

### 6.3 Runnable examples everywhere (RESOLVED)

**Done.** There is no `\dontrun{}` left in the package. The eleven remaining
blocks were either referencing objects that were never defined
(`NewtonRaphsonControl`, `gaussian_scale_summary`, `mlpe_response_change`) or
self-contained but too slow to run under check. All are now complete,
runnable `\donttest{}` examples on the bundled `melip` data or a small
synthetic lattice.

Where a raster made an example slow, it is coarsened with
`terra::aggregate(fact = 3)` and a comment says to use the full resolution in a
real analysis; `fact = 3` was chosen because it is three times faster while
still reproducing the full-resolution coefficient signs and magnitudes
(`fact = 4` flips the forest-cover sign). Every one of the fifteen affected
topics was executed and timed: all pass, and the set totals about 65 seconds,
with the slowest single topic at 14 seconds.

Two accuracy problems surfaced while making these runnable:

* `terradish_scale_optim()`'s example used `lower = 50, upper = 500`, but the
  default `scale_fun` (`multiScaleR::kernel_scale.raster`) measures sigma in
  raster **cells**, not map units. On a 156-by-180 raster those bounds smooth
  the layer into a constant. The `@param lower,upper` documentation now states
  the units and gives a usable starting range, and the example uses 1 to 6
  cells, which produces a genuine AIC spread of about 225 across the four
  candidates.
* `terradish_scale_optim()`'s `@return` listed seven components in one line
  each. It now documents what every component means, that `value` is the
  objective and `objective` is its *name*, and how to read the `evaluations`
  table (including that a flat objective column means the data do not identify
  a scale of effect).

## 7. Open items: resolved

All six were dispositioned by the maintainer.

1. **`terradish_parameters(save_table = TRUE)`**: left as is, by decision. The
   write goes to a directory the caller supplied for exactly this purpose.
2. **`melip` primary source citation**: no further detail available, so the
   `@source` stands as written. It records what is verifiable (redistributed
   from `radish`) and states plainly that no primary citation is recorded in
   the package sources. Nothing was invented.
3. **Installed size**: fixed. The vendored `amgcl` header library went from 137
   files (1.56 MB) to 25 (312 KB), a 1.25 MB saving. The kept set is the
   transitive `#include` closure of the seven amgcl headers included from
   `src/*.cpp`, computed by static analysis; there are no macro-constructed
   includes in amgcl, so the closure is exact. Everything removed was an
   unbuilt backend: MPI (45 files), plus CUDA, VexCL, Eigen, and Epetra
   adapters. Verified twice, by a clean `R CMD INSTALL --preclean` and by an
   independent full rebuild, and the AMG solver tests pass unchanged. This also
   removes the deepest paths in the tarball, which were the source of the
   Windows `MAX_PATH` failures noted during this audit.
4. **`configure` and `cleanup` file modes**: fixed with
   `git update-index --chmod=+x`, so both are now tracked `100755`.
5. **Loop bounds**: fixed. `1:length()` in `mlpe.R`, `1:length()` and
   `1:nrow()` in `radish_optimize.R` became `seq_along()`, `seq_len()`, and
   `sample.int()`. The two `1:maxit` loops in the optimizers were also
   converted, which required adding an up-front `maxit` validator: those loops
   define the variables the post-loop convergence check reads, so
   `seq_len(0)` would leave them unbound where `1:0` silently iterated twice.
   `maxit = 0` now errors clearly. No `1:n` idiom remains in `R/`.
6. **Undocumented methods**: fixed. `print.terradish_covariance_power` and
   `print.terradish_setting_assessment` each gained a full help page with a
   "how to read the output" walkthrough, `\seealso`, and a runnable example.
   `?terradish_methods` and `?terradish_cv_replicates_methods`, which had
   neither examples nor `\seealso`, gained both; the latter also gained
   guidance on reading the mean and standard deviation of the held-out
   log-likelihood and on when two models are not separable.

**All 47 registered S3 methods now have a help page**, and every exported topic
has `alue`, `\examples`, and no `\dontrun`.
